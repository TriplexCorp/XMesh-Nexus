# XSP-v2 P0-E v5 AI-assisted security review — 31 October 2026

## Decision

The project no longer requires a paid or organizationally independent external security reviewer as a mandatory release gate for the current KVM VPS deployment class.

The replacement assurance model is:

> **complete AI-assisted internal security review of the exact frozen target + explicit release-owner risk acceptance + all existing technical release gates**.

This is an intentional governance change, not a claim that the review became independent. The machine-readable result therefore requires `reviewer.independent=false` and records the release owner's explicit acceptance of the reduced organizational-independence assurance.

The external-review bundle and old independent-review contract are retained as historical/optional evidence. A later third-party audit can still be performed, but it is not a prerequisite for this release sequence.

1. the earlier full AI-assisted audit of all 11 security domains;
2. exact source delta review from Nexus `0bab1a48...` to the current frozen runtime `12b31709...`;
3. exact source delta review from Node `083dc181...` to `34d3d7e...`;
4. the v5 deterministic reviewer bundle;

CI and live evidence are corroboration. They do not replace source/trust-boundary reasoning.

## Delta review from the earlier internal audit

The earlier internal audit found two Low findings.

### AI-LOW-001 — remediated

The previous ingress used `ssl_verify_client optional` and rejected unauthenticated clients at the route layer. The current frozen Nexus ingress uses:

```nginx
ssl_verify_client on;
```

while retaining exact routes, TLS-derived identity headers, TLS 1.3, `X25519MLKEM768`, unknown-SNI rejection and the protected UDS boundary.

Result: the prior Low availability/authentication-policy hardening finding is **remediated** in the current frozen target.

### AI-LOW-002 — remediated

The earlier Node master-key creation fsynced the new key file but did not fsync the containing directory entry. The current frozen Node target calls `syncParentDir(path)` after a successful key-file fsync/close and includes a Linux durability regression test.

Result: the prior Low provisioning-durability finding is **remediated** in the current frozen target.

No other production-runtime security-relevant delta was identified between the earlier reviewed implementation and the current frozen runtime that creates a new unresolved release-blocking finding.

## Current review disposition

**APPROVE WITH INFORMATIONAL / ACCEPTED-RISK FINDINGS.**

No unresolved Critical, High, Medium or Low release-blocking vulnerability was identified for the current frozen target.

The two retained informational boundaries are:

1. **KVM provider storage durability is an external trust boundary.** The release relies on provider-managed block storage honoring durable guest flush semantics. `physicalPowerLossQualified=false` remains mandatory.
2. **The review is not organizationally independent.** The release owner explicitly accepts that reduced assurance rather than representing the AI-assisted review as a third-party audit.

Neither item removes any technical gate.

## What this policy change does not waive

The following remain mandatory:

- exact frozen runtime target binding;
- #138 KVM durability qualification;
- provider-storage risk acceptance;
- exact-candidate final canary after the security gate is accepted;
- reviewed production rollout/rollback evidence;
- TLS 1.3 only;
- `X25519MLKEM768` key exchange;
- ML-DSA-65 client identity;
- Ed25519 **and** ML-DSA-65 critical-message signatures;
- `automaticFallback=false`;
- `classicalOnlyAllowed=false`;
- bounded named-Node activation approval;
- `legacyXMESH1Action=retain` until separately retired;
- a separate production execution step.

Before that separate execution step:

```text
physicalPowerLossQualified=false
productionActivation=false
strictPQEnabled=false
legacyXMESH1Retired=false
```

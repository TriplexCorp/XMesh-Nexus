# Клиентская маршрутизация по нодам и публичным хостам

Новый раздел **Управление → Маршрутизация клиентов** работает только с клиентскими
подписками Xray JSON. Он не меняет маршрутизацию Xray на ноде (раздел
**Узлы → Маршрутизация** по-прежнему отвечает за *серверный* трафик).

## Общие шаблоны без дублирования

Создайте один шаблон «RU через Польшу». Укажите правила в порядке приоритета:

| Условие | Значение | Действие |
| --- | --- | --- |
| GeoSite | `category-ru` | Через другой сервер → `host:<ID_польского_хоста>` |
| GeoIP | `ru` | Через другой сервер → тот же польский хост |
| Домен | `example.com` | Напрямую |
| Порт | `25` | Блокировать |

Отметьте в **Назначить серверам** все ноды, которым нужна эта маршрутизация,
например Нидерланды и Швецию. Для особого публичного CDN-хоста можно отметить
`host:<ID>` в *другом* шаблоне — он переопределит унаследованный шаблон ноды.

Одна и та же нода может иметь несколько исходящих подключений. Назначение
`node:<ID>` применяется ко всем её одиночным клиентским профилям.
Чтобы назначить только один из публичных хостов — используйте `host:<ID>`.

### Реализация в клиентском JSON

Каждый одиночный сервер в подписке остаётся отдельной полноценной конфигурацией
Happ / Xray. Его дополнительные правила вставляются перед итоговым
маршрутом через выбранный сервер, **после** базовой защиты приватных адресов
и перехвата DNS (если включён). Общие балансировщики остаются самостоятельными
профилями: маршрутизация отдельных серверов на них автоматически не переносится.

Для действия **«Через другой сервер»** соответствующий outbound добавляется
в клиентский JSON из *уже авторизованных подключений этого пользователя*.
Если целевой сервер отсутствует в его подписке, правило использует `block`,
**не** подменяя направление на direct или случайный сервер.

### Источник назначения

- Явно назначенный шаблон `host:<ID>` имеет приоритет.
- Иначе применяется шаблон `node:<ID>` только для публичного хоста, имеющего
  единственного владельца среди активных нод XRAY STUDIO.
- Хост, принадлежащий нескольким нодам, не наследует маршрут автоматически.
  Назначайте таким CDN-хостам собственный шаблон.
- Для узла без публичного хоста применяется шаблон `node:<ID>`.

Все настройки хранятся как `clientRoutingProfiles` в PostgreSQL
(`app_settings`, раздел `panel`), доступны через администраторскую страницу
с проверкой прав на сохранение. В Xray JSON не включаются внутренние
`xmeshSourceKey` / `xmeshOwnerNodeKey`.

Пример проверяемой схемы:

```json
{
  "clientRoutingProfiles": [
    {
      "id": "ru-route",
      "name": "RU через Польшу",
      "enabled": true,
      "servers": ["node:10", "host:31"],
      "rules": [
        {"match": "geosite", "value": "category-ru", "action": "server", "server": "host:52"},
        {"match": "geoip", "value": "ru", "action": "direct"},
        {"match": "domain", "value": "example.org", "action": "block"}
      ]
    }
  ]
}
```

### Важные ограничения

- Для GeoSite/GeoIP на устройстве должны быть доступны соответствующие категории
  GeoData; наличие GeoData на сервере не гарантирует их наличие у клиента.
- Xray отправляет запросы согласно правилам клиента. Это не переопределяет
  сетевую политику установленной ноды или принудительное отключение подписок.
- Нельзя назначить один и тот же сервер двум шаблонам одновременно.
- Лимиты: до 64 шаблонов, 64 правил в шаблоне и 256 серверов на шаблон.
- Специальные действия, неизвестные поля, управляющие символы и опасные
  селекторы отклоняются на стороне Rust API; роль наблюдателя не получает
  доступ к данным шаблонов.

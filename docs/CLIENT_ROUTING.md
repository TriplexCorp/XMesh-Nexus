# Клиентская маршрутизация по нодам и публичным хостам

Новый раздел **Управление → Маршрутизация клиентов** работает только с клиентскими
подписками Xray JSON. Он не меняет маршрутизацию Xray на ноде (раздел
**Узлы → Маршрутизация** по-прежнему отвечает за *серверный* трафик).

## Индивидуальная маршрутизация пользователя

В карточке **Пользователи → пользователь → Маршрутизация** доступны два режима:

- **Наследовать глобальные** — поведение без изменений, как до добавления функции.
- **Индивидуальные правила** — добавляет исключения для выбранного пользователя.
  Исключения выполняются **перед** правилами общего шаблона хоста/ноды.
  Остальные запросы продолжают обрабатываться глобальным шаблоном.

Например, для Ивана можно назначить правило `GeoSite = youtube` →
`host:<RU>`, а для Семпатина — то же условие → `host:<GB>`.
Оба пользователя по-прежнему наследуют остальные правила маршрутизации
своих подключений. Изменение одного пользователя не меняет настройки другого.

Порядок приоритета в каждом **одиночном** клиентском Xray JSON:

1. Обязательные системные маршруты клиента (DNS/защита локальных адресов).
2. Персональные правила пользователя в заданном порядке.
3. Глобальный шаблон, назначенный публичному хосту или ноде.
4. Маршрут по умолчанию через выбранное подключение.

Персональные правила сохраняются вместе с карточкой пользователя единым
`PATCH /collections/users/{id}`, в JSON-поле `clientRouting`:

```json
{
  "clientRouting": {
    "mode": "custom",
    "rules": [
      {"match": "geosite", "value": "youtube", "action": "server",
       "server": "host:31", "network": "tcp,udp"}
    ]
  }
}
```

`{"mode":"inherit","rules":[]}` возвращает полное наследование.
В режиме «Наследовать» редактор не отправляет устаревшие личные правила.
Для персональных правил действует тот же безопасный Rust-валидатор, что и
для общих, с отдельным лимитом 32 правила на пользователя. Поддержаны
GeoSite, GeoIP, домен, IP/CIDR и порт, действия: основной сервер, другой
сервер, напрямую, блокировать, а также фильтр TCP/UDP.

**Граница доступа:** цель `server` выбирается только из реальных
подключений **этого** пользователя. Если выбранный хост отсутствует в его
разрешённой подписке, Xray получает `block` для этого условия; маршрутизация
не раскрывает чужие узлы и не перепрыгивает в `direct`. Администраторский
предпросмотр JSON и публичная подписка используют один и тот же механизм.
Внутренние идентификаторы источников остаются вне клиентского JSON.

Новый режим касается только клиентского Xray JSON. Он не изменяет глобальные
шаблоны, серверный Xray routing, ограничения доступов, внешний IP самой ноды
или режим выдачи подписки. Изменения вступают в силу после обновления
подписки клиентом.

## Компактный каталог маршрутизации

Раздел использует единый компактный тулбар со счётчиком шаблонов и
действием «Новый шаблон». Повторного крупного заголовка «Шаблоны» под
основным названием страницы нет. На широких экранах небольшое число карточек
распределяется по доступной ширине без пустой зарезервированной колонки;
одна карточка при этом не растягивается в нечитаемо широкую форму.

В обзоре шаблона показаны его состояние, назначения и упорядоченный список
правил. Клик по назначению или правилу открывает соответствующее поле
редактора. Сворачивание карточки, копирование шаблона и появление панели
сохранения несохранённых правок должны работать независимо от оформления.
Токены плотности, темы и скругления наследуются от общего дизайн-системного
слоя; для узких экранов карточки перестраиваются без горизонтальной прокрутки.

## Общие шаблоны без дублирования

Создайте один шаблон «RU через Польшу». Укажите правила в порядке приоритета:

| Условие | Значение | Действие |
| --- | --- | --- |
| GeoSite | `category-ru` | Через другой сервер → `host:<ID_польского_хоста>` |
| GeoIP | `ru` | Через другой сервер → тот же польский хост |
| Домен | `example.com` | Напрямую |
| Порт | `25` | Блокировать |

Отметьте в **Назначить серверам** все ноды, которым нужна эта маршрутизация,
например Нидерланды и Швецию. Для особого публичного CDN-хоста можно отметить
`host:<ID>` в *другом* шаблоне — он переопределит унаследованный шаблон ноды.

Одна и та же нода может иметь несколько исходящих подключений. Назначение
`node:<ID>` применяется ко всем её одиночным клиентским профилям.
Чтобы назначить только один из публичных хостов — используйте `host:<ID>`.

### Реализация в клиентском JSON

Каждый одиночный сервер в подписке остаётся отдельной полноценной конфигурацией
Happ / Xray. Его дополнительные правила вставляются перед итоговым
маршрутом через выбранный сервер, **после** базовой защиты приватных адресов
и перехвата DNS (если включён). Общие балансировщики остаются самостоятельными
профилями: маршрутизация отдельных серверов на них автоматически не переносится.

Для действия **«Через другой сервер»** соответствующий outbound добавляется
в клиентский JSON из *уже авторизованных подключений этого пользователя*.
Если целевой сервер отсутствует в его подписке, правило использует `block`,
**не** подменяя направление на direct или случайный сервер.

### Источник назначения

- Явно назначенный шаблон `host:<ID>` имеет приоритет.
- Иначе применяется шаблон `node:<ID>` только для публичного хоста, имеющего
  единственного владельца среди активных нод XRAY STUDIO.
- Хост, принадлежащий нескольким нодам, не наследует маршрут автоматически.
  Назначайте таким CDN-хостам собственный шаблон.
- Для узла без публичного хоста применяется шаблон `node:<ID>`.

Все настройки хранятся как `clientRoutingProfiles` в PostgreSQL
(`app_settings`, раздел `panel`), доступны через администраторскую страницу
с проверкой прав на сохранение. В Xray JSON не включаются внутренние
`xmeshSourceKey` / `xmeshOwnerNodeKey`.

Пример проверяемой схемы:

```json
{
  "clientRoutingProfiles": [
    {
      "id": "ru-route",
      "name": "RU через Польшу",
      "enabled": true,
      "servers": ["node:10", "host:31"],
      "rules": [
        {"match": "geosite", "value": "category-ru", "action": "server", "server": "host:52"},
        {"match": "geoip", "value": "ru", "action": "direct"},
        {"match": "domain", "value": "example.org", "action": "block"}
      ]
    }
  ]
}
```

### Важные ограничения

- Для GeoSite/GeoIP на устройстве должны быть доступны соответствующие категории
  GeoData; наличие GeoData на сервере не гарантирует их наличие у клиента.
- Xray отправляет запросы согласно правилам клиента. Это не переопределяет
  сетевую политику установленной ноды или принудительное отключение подписок.
- Нельзя назначить один и тот же сервер двум шаблонам одновременно.
- Лимиты: до 64 шаблонов, 64 правил в шаблоне и 256 серверов на шаблон.
- Специальные действия, неизвестные поля, управляющие символы и опасные
  селекторы отклоняются на стороне Rust API; роль наблюдателя не получает
  доступ к данным шаблонов.

# Индивидуальные квоты пользователя по нодам

XMesh Nexus поддерживает независимые квоты по каждой ноде для каждого пользователя поверх общего лимита и CDN-пула.

| Нода | Лимит | Период |
| --- | ---: | --- |
| A | 1000 ГБ | За всё время |
| B | 847 ГБ | Ежемесячно, UTC |
| C | 5 ГБ | Еженедельно, с понедельника 00:00 UTC |
| D | 1 ГБ | Ежедневно, с 00:00 UTC |

Пользователь продолжит иметь доступ на A и B, даже когда C исчерпает свои 5 ГБ. Общая политика пользователя, квота CDN и локальная квота ноды действуют одновременно.

## Настройка

При создании пользователя используйте сразу видимый блок **Квоты по нодам** под основными карточками, укажите лимит и период для нужных нод и нажмите **Создать пользователя**. Политики отправляются в одном POST при создании; отдельного PATCH после создания нет. Поле пустое или 0 означает безлимит. 

Для существующего пользователя откройте Пользователи → Карточка пользователя → Трафик → Индивидуальные квоты нод. Выберите для каждой ноды число ГБ больше нуля и период. Ноль или пустое поле означают отсутствие локального ограничения. Нажмите общую кнопку **Сохранить изменения** в карточке пользователя.

Сохранение: штатный PATCH /api/v1/collections/users/{id} в поле nodeTrafficLimits:

    {
      "nodeTrafficLimits": {
        "12": {"limitGb": 1000, "period": "lifetime"},
        "34": {"limitGb": 847, "period": "monthly"},
        "56": {"limitGb": 5, "period": "weekly"},
        "78": {"limitGb": 1, "period": "daily"}
      }
    }

Сервер проверяет существующие ID нод, диапазон лимитов и периоды. До 256 нодовых квот одному пользователю. Поле nodeQuotaUsedBytes — только временный серверный счётчик, любые попытки записать его через пользовательский API отклоняются.

## Источники данных

- user_node_quota_lifetime — отдельный пожизненный журнал, не зависящий от ручного сброса общей статистики user.used.
- user_node_quota_monthly — отдельный журнал с началом периода в 00:00:00 первого числа месяца UTC.
- user_node_quota_weekly — отдельный журнал с началом ISO-недели в понедельник в 00:00:00 UTC.
- user_node_quota_daily — отдельный журнал с началом суток в 00:00:00 UTC.
- Принимаются только положительные дельты подписанного user traffic в разрезе node_id + user_id. Inbound counters не прибавляются к user counters. Первое наблюдение, повтор и сброс Xray-счётчика не начисляют искусственный расход.
- Миграция 0115 переносит существующие lifetime агрегаты и проверенные дельты текущего месяца. Миграция 0116 заполняет только текущую неделю и текущий день из уже сохранённых проверенных user-дельт. Отсутствующие исторические показания не восстанавливаются и не придумываются.
- Единица лимита — десятичный ГБ (1 000 000 000 байт). Остаток/блокировка считают целые байты; округляется только визуальная подпись.

## Блокировка Xray

При выдаче подписанного desired-config конкретной ноде бэкенд загружает серверные счётчики и не включает UUID/учётные данные исчерпавшего лимит пользователя в inbound clients/users. На других нодах доступ остаётся. Величина расхода из браузера никогда не принимается.

Это ограничение зависит от регулярной синхронизации агента: отключение **не является мгновенным packet-level cutoff**. До следующего применения desired-config и закрытия уже установленных соединений возможен перерасход. Для жёсткой немедленной блокировки нужен отдельный потоковый контроль на агенте. Подписанная офлайн-политика при этом ограничивает бюджет локальным остатком ноды.

## Отчёты

GET /api/v1/users/{id}/node-quotas — авторизованный серверный отчёт с расходом, остатком и состоянием по каждой ноде. Удалённая нода с сохранённым правилом не пропадает бесследно из отчёта и может быть удалена администратором.

## Переменные Remark

- NODE_DATA_LEFT — индивидуальный остаток лимита однозначно привязанной ноды.
- TRAFFIC_LEFT — сначала индивидуальный лимит ноды (если он есть), иначе CDN-квота для CDN-inbound, иначе общий остаток пользователя.
- CDN_DATA_LEFT и DATA_LEFT сохраняют прежний смысл.

Если Host направлен на несколько нод с независимыми квотами, невозможно честно показать единый остаток: возвращается —. Для раздельных лимитов рекомендуется отдельный Host для каждой ноды. Если на всех нодах локальные квоты отсутствуют, TRAFFIC_LEFT сохраняет выбор общего/CDN-пула.

## Инварианты и ограничения

1. Подписанная телеметрия — единственный источник расхода.
2. Общий лимит пользователя, CDN-квота, персональная квота ноды и node-wide bandwidth cutoff не подменяют друг друга.
3. Сброс общей статистики пользователя не обнуляет квоты нод.
4. Идентификаторы нод стабильны и положительны; клиентские UUID не используются как ключи журналов.
5. Смена суток, ISO-недели (понедельник) и месяца UTC не требует фонового задания. Все четыре журнала пополняются из одной и той же положительной проверенной дельты в одной транзакции; новая календарная корзина стартует с нуля без сброса/потери накопительного lifetime.
6. Ошибка чтения авторитетного счётчика блокирует выдачу нового desired-config; ошибка только метки Remark показывает — без повреждения подписки.

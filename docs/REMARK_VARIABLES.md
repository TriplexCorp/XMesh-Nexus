# Динамические Remark в XMesh Nexus

В разделах Хосты → Подключение и XRAY STUDIO → Публичные подключения поле Название / Remark поддерживает динамические переменные. Подстановка выполняется при каждом запросе подписки, но сохранённый шаблон Host остаётся неизменным.

Пример: 🇩🇪 Германия · {STATUS_EMOJI} {USERNAME} · {DATA_LEFT} · {DAYS_LEFT} д.

## Переменные

| Переменная | Назначение |
| --- | --- |
| {SERVER_IP} | Публичный IPv4 прямого подключения |
| {SERVER_IPV6} | Публичный IPv6 прямого подключения |
| {USERNAME} | Имя пользователя |
| {DATA_USAGE} | Использованный трафик |
| {DATA_LEFT} | Остаток трафика |
| {DATA_LIMIT} | Общий лимит трафика пользователя |
| {CDN_DATA_LEFT} | Остаток *общего CDN-пула пользователя*, независимо от Host |
| {NODE_DATA_LEFT} | Остаток индивидуальной квоты пользователя для однозначно назначенной ноды |
| {TRAFFIC_LEFT} | Приоритет: индивидуальная квота ноды → CDN-пул → общий остаток пользователя |
| {DAYS_LEFT} | Оставшиеся дни (округление вверх) |
| {TIME_LEFT} | Дни, часы и минуты |
| {EXPIRE_DATE} | Дата окончания (UTC) |
| {JALALI_EXPIRE_DATE} | Дата по календарю Джалали |
| {STATUS_TEXT} | Текущий статус пользователя |
| {STATUS_EMOJI} | Настраиваемый эмодзи статуса |
| {PROTOCOL} | Протокол подключения |
| {TRANSPORT} | Транспорт Xray |

Данные DATA_USAGE/DATA_LEFT/DATA_LIMIT берутся из общего учёта user.used/user.limit (не из конкретной ноды).
Для CDN_DATA_LEFT используется отдельная квота user.cdnLimitGb и серверный счётчик, прочитанный из user_inbound_traffic_monthly (текущий месяц UTC) либо user_inbound_traffic_totals (lifetime). Это **общая CDN-квота пользователя на все отмеченные CDN-ноды**, а не индивидуальный лимит ноды.
Цифры считаются в целых байтах (1 ГБ = 1 000 000 000 байт), округление до сотых ГБ делается только для подписей.
При недоступном серверном счётчике и конечном CDN-лимите отображается «—», а подписка не отключается из-за ошибки вывода метки.

TRAFFIC_LEFT выбирает тип подключения по действительным привязкам Host → enabled Nodes → inbound/tag и настройкам node.cdnMode/cdnInboundTags либо глобальным cdnInboundTags.
Если все соответствующие ноды относятся к одному типу квоты, отображается этот тип; если назначения смешаны (обычная + CDN-нода), отсутствуют или некорректны, отображается «—», а не выдуманное значение.
Значения не вычисляются по флагу страны, имени хоста, адресу CDN или географии. У Host с несколькими CDN-нодами отображается общий CDN-пул; смешанный Host следует явно разделить на два Host.

**Перспектива тонких лимитов на нодах:** генератор теперь передаёт context.owner_node_id, если однозначно известна одна нода. В будущем в этот контекст можно добавить квоту конкретного node_id и отдельные правила принудительной блокировки. Лимиты «A — 1000 ГБ, B — 847 ГБ, C — 5 ГБ» пока НЕ внедрены: хранение, учёт, лимитирование и безопасные сбросы на уровне каждой ноды потребуют отдельной реализации. Текущий CDN-пул общий.

Единицы — десятичные ГБ. При отсутствии лимита/срока выводится ∞. Подписки с отсчётом от первого подключения показывают отдельный статус ожидания.

## Настройка эмодзи

В SUBSCRIPTION STUDIO → Клиентский портал → Эмодзи статусов в Remark редактируются значения ACTIVE (✅), ON_HOLD (⌛️), LIMITED (🪫), EXPIRED (❌), DISABLED (🔌). Данные сохраняются в subscriptionStatusEmojis в настройках панели, без правок .env.

## Безопасность и совместимость

- Серверные подстановки касаются только клиентского имени; Xray routing tags и UUID не меняются.
- Для CDN-домена и hostname {SERVER_IP}/{SERVER_IPV6} показывают —. Скрытый IP origin-ноды не раскрывается.
- Неизвестные переменные остаются без изменений. Подстановка однопроходная, без рекурсии.
- Итоговое имя ограничено 100 символами; управляющие символы удаляются.
- Изменения видны после следующего обновления подписки клиентом, не мгновенно.
- Публичная выдача по-прежнему блокируется для отключённых/истёкших пользователей согласно существующей политике доступа.

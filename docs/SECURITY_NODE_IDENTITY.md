# XMesh Nexus — защита Control Plane и идентичность узлов

## Что уже реализовано

- **Администраторы:** Argon2-хеши паролей; серверные отзываемые сессии в PostgreSQL;
  `HttpOnly` + `SameSite=Strict` cookie и `Secure` при HTTPS; TOTP, recovery codes,
  роли owner/admin/viewer; ограничения входа, аудит, проверка CSRF.
- **Агенты метрик:** Ed25519 proof-of-possession для каждого узла. Приватный ключ
  хранится **только на узле**; PostgreSQL хранит публичный. Старый Bearer автоматически
  удаляется **для этого узла** при регистрации публичного ключа.
- **Replay protection:** подписываются HTTP method, URL path, node id, timestamp
  (+/- 120 секунд), 128-битный случайный nonce и SHA-256 исходного JSON.
  Успешно проверенный nonce атомарно помечается использованным в PostgreSQL.
  Повторное использование выдаёт HTTP 401.
- **Отзыв:** владелец может удалить ключ, после чего все учётные данные узла
  недействительны. Ротация — регистрация нового публичного ключа, которая
  отзывает старый ключ.
- **Передача:** агент требует HTTPS и системные сертификаты. Не применяйте
  `curl -k`, `--insecure` и отключение проверки сертификатов.

## Перевод существующего узла

1. Обновите Control Plane (GitHub CI должен быть зелёным); сделайте резервную копию.
2. В панели откройте **Узлы → Настроить метрики**. Скопируйте команду установки.
   Установщик создаст (или сохранит) `/etc/xmesh-node-metrics/node.key` с правами `0640` и владельцем `root:xmesh-metrics`.
3. Скопируйте **публичный** ключ из терминала узла в поле панели, нажмите
   «Активировать защищённый агент». Контроллер сохраняет публичный ключ
   и немедленно отзывает старый Bearer-токен этого узла.
4. Проверьте отправку: `sudo systemctl start xmesh-node-metrics.service`, затем
   `journalctl -u xmesh-node-metrics.service -n 30 --no-pager`.
5. Повторите для каждого узла. До регистрации ключа старые агенты могут
   использовать свои ранее выданные Bearer-токены. Это намеренный временный
   режим совместимости, **не** максимально строгая модель.

**Не передавайте приватный ключ в UI, логи, командную строку или Git.**
Если приватный ключ украден, немедленно отзовите ключ через интерфейс,
сгенерируйте новый ключ на узле и зарегистрируйте новый публичный ключ.
Кража приватного ключа по-прежнему позволяет злоумышленнику создавать
валидные подписи до его отзыва — Ed25519 не заменяет защиту самого узла.

## Формат подписанного запроса

URL: `POST /api/v1/metrics/ingest`

Заголовки:

```text
X-XMesh-Timestamp: <unix-seconds>
X-XMesh-Nonce: <32 lowercase hex>
X-XMesh-Signature: <128 hex of Ed25519 signature>
Content-Type: application/json
```

Подписываемое сообщение — UTF-8, строки разделены LF, включая последний LF:

```text
XMESH1
POST
/api/v1/metrics/ingest
<node_id>
<unix-seconds>
<nonce>
<lowercase hex SHA-256 of unmodified HTTP body>
```

Запрос нельзя просто переиграть, потому что nonce одноразовый, а метка
времени проверяется независимо. Администратор регистрирует ключ по
`POST /api/v1/nodes/{id}/metrics-key` с JSON `{"publicKey":"<64 hex>"}`.
Для удаления: `DELETE /api/v1/nodes/{id}/metrics-key`. Эти API требуют
авторизованной owner-сессии и корректного Origin.

## Оставшиеся уровни защиты (не считайте реализованными)

1. **mTLS на HTTPS reverse proxy** для отдельного агентского endpoint. Сертификат
   узла должен проверяться самим доверенным прокси, не на основании произвольного
   `X-Client-Cert` заголовка из интернета. В текущем Rust API этого пока нет.
2. **Сетевой периметр:** закрыть Control Plane за WireGuard/Tailscale или
   IP allowlist; не открывать порт 8080, PostgreSQL и Redis.
3. **Passkeys/WebAuthn** и повторная авторизация для критических операций.
4. **Секреты и аудит:** вынос долгоживущих ключей из `.env`, управление ротацией,
   проверка restore из backup и независимый pentest.
5. **Legacy bearer:** для чистых установок по умолчанию запрещён (`ALLOW_LEGACY_NODE_BEARER=false`). На существующих установках `install.sh` сохраняет временную совместимость (`true`), пока идёт миграция. После перевода всех узлов выставьте `false` в `.env` и пересоздайте контейнер (`docker compose up -d --no-deps --force-recreate panel`). Когда все
   узлы перейдут на Ed25519, имеет смысл добавить политику глобального
   отключения legacy. До этого глобальный запрет вызовет потерю метрик.

## Операционные замечания

- Системные часы должны быть синхронизированы (NTP). Окно ±120 секунд.
- Регистрация публичного ключа нового узла намеренно не происходит
  автоматически: владелец должен подтвердить доверие конкретной машине.
- Сертификат публичного HTTPS-сайта защищает канал; криптографическая
  подпись дополнительно удостоверяет *узел*, даже при утечке старого Bearer.
- Статические тесты и CI не заменяют сетевой аудит production VPS.

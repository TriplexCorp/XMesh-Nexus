# XRAY STUDIO — Enterprise JSON Workspace

## Назначение

XRAY STUDIO — единая JSON-first рабочая область для подготовки, проверки и сохранения серверных конфигураций Xray. Главный редактор занимает основную часть экрана; дополнительные инструменты и read-only навигация не должны прерывать ручное редактирование.

## Конструктор конфигураций (вместо каталога из 12 шаблонов)

XRAY STUDIO содержит отдельный **комбинационный движок**, `xray-studio-composer.js`. Источник правды — три независимых измерения, а не отдельная реализация каждого готового сценария:

1. **Протокол:** VLESS, VMess, Trojan, Shadowsocks, SOCKS, HTTP, Hysteria2, MASQUE, пользовательский идентификатор для будущих версий ядра.
2. **Транспорт:** RAW, XHTTP, gRPC, WebSocket, HTTPUpgrade, mKCP, Hysteria, MASQUE или собственное название.
3. **Защита:** none, TLS, REALITY.

По текущей таблице совместимости Xray движок знает **92 документированных сочетания** до учёта методов Shadowsocks, путей, режимов XHTTP, свойств транспортов и расширенного JSON. Поддержка комбинаций определяется по документации и окончательно — `xray -test` установленного ядра. Неизвестная или неподдерживаемая комбинация не исчезает из интерфейса: выводится причина, а создание экспериментального JSON требует явного подтверждения. Наличие в каталоге не является гарантией совместимости с конкретной версией ядра.

В частности, **Shadowsocks × XHTTP × REALITY** доступен и как ручная комбинация, и как быстрый сценарий. Для Shadowsocks и SOCKS показывается предупреждение, что обычный UDP может обходить выбранный транспорт/защиту без соответствующей схемы XUDP.

Рабочее окно содержит выбор трёх параметров, имя профиля, tag/listen/port, дополнительные поля выбранного протокола, предпросмотр *только серверного inbound*, сообщения о совместимости и отдельную вкладку «Быстрый старт». Быстрые сценарии **подставляют значения в конструктор, но не закрывают его** и не ограничивают ручной выбор.

Есть два применения:

- **Новый профиль:** после подтверждения несохранённых изменений создаётся новый документ и черновик в редакторе.
- **Добавить inbound:** старые inbounds, outbounds, routing, пользовательские поля и имя профиля сохраняются; дублирование tag отклоняется. Другие объекты не переписываются.

Пароль Shadowsocks 2022 генерируется криптографическим CSPRNG (16 или 32 байта в зависимости от метода) **только при создании**. Для REALITY при наличии заполненных target и SNI через переданный генератор WebCrypto создаётся пара X25519 и новый HEX Short ID. Превью не показывает ещё не созданные секреты. Public key копируется в буфер по возможности. Необходимо проверить полученный серверный JSON и клиентские параметры перед применением к ноде.

Дополнительные настройки и нестандартные поля доступны в полном JSON-редакторе без преобразования через ограниченный конструктор. Ни один из пресетов не заменяет ручной JSON.

## Структура интерфейса

- **Product header:** название, назначение и метка JSON FIRST, без дублирующих навигационных панелей.
- **Главная панель:** две понятные вкладки «JSON-редактор» и «Профили». Проверка ядром, шаблоны, импорт, экспорт и сохранение сгруппированы справа.
- **Файл:** название профиля, `config.json`, статус несохранённых изменений, Undo/Redo и переключатель «Структура». Кнопки дублирующего форматирования и увеличения удалены.
- **Контекстные инструменты:** кнопки вычисляются по текущим `inbounds[].protocol`, `streamSettings.network` и `streamSettings.security`. Для Hysteria2 показываются редактирование `hysteriaSettings`, TLS и параметров протокола вместо REALITY/VLESS; для VLESS доступны соответствующие REALITY, Short ID, Encryption и Vision (в зависимости от конфигурации). XHTTP и другие настройки транспорта доступны только в соответствующем контексте. DNS, Routing, Outbounds и создание inbound — общие инструменты.
- **Несколько inbound:** в панели инструментов появляется селектор соединения. Он одновременно определяет видимые инструменты и inbound, к которому применяется действие. При переключении шаблона, профиля или ручном редактировании JSON набор инструментов обновляется автоматически, без пересоздания редактора. При ошибке JSON редактирующие инструменты временно недоступны.
- **Редактор:** синтаксическая подсветка, номера строк, курсор, предупреждения семантической диагностики, перенос строк и мини-карта. JSON остаётся источником истины.
- **Структура:** интерактивный read-only инспектор с количеством inbound/outbound/правил, переходами по JSON, краткой информацией о тегах, протоколах и транспортах, а также статусом проверки. Он **никогда не показывает privateKey, пароли, UUID или прочие секреты**.
- **Нижняя полоса:** состояние сохранения и подтверждаемое действие сброса.

## Адаптивность и персонализация

Сетка использует доступную ширину `.wrap`, которая управляется пользовательской настройкой `--panel-content-max`. Размеры текста основаны на rem и глобальном `--ts`, скругления — на `--ui-control-radius` и `--ui-radius`, цвета — на пользовательских токенах темы.

На широких экранах read-only инспектор расположен справа; на узких экранах — под редактором. Пользователь может скрыть структуру, полностью отдав ширину JSON. Состояние сохраняется локально под ключом `xmesh-studio-inspector`. Для анимаций поддерживается `prefers-reduced-motion`.

## Безопасность и логика

- Неправильный исходный JSON не перезаписывается конструктором или инструментами.
- Неизвестные поля Xray сохраняются при точечных изменениях.
- Подозрительные и некорректные значения REALITY отклоняются клиентской и серверной валидацией, а генерация ключей требует подтверждения при ротации.
- Профиль сохраняется в PostgreSQL, но это **не означает автоматического применения к ноде**.
- Статус «JSON корректен» не равен успешной проверке Xray-core. Отдельная кнопка «Проверить» отправляет документ на backend для `xray -test`; интерфейс должен отличать эти состояния.
- Старый конструктор остаётся технически смонтированным и скрытым для совместимости с обработчиками синхронизации и публичными хостами. Он не является второй пользовательской рабочей областью.

## Исходники и тесты

- `xray-studio-v4.js` — представление, библиотека, инспектор, навигация, сохранение.
- `xray-studio-v4.css` — единая система оформления и адаптивности (прежние конфликтующие слои удалены).
- `xray-studio-tools.js` — контекстная палитра по протоколу/транспорту/защите, селектор inbound, точечные редакторы Hysteria2/TLS/протокола/транспорта и безопасные операции с JSON.
- `xray-studio-composer.js` — независимая матрица конфигураций, проверка сочетаний и безопасная генерация server-side inbound.
- `scripts/check-xray-studio-composer.js` — регрессии комбинаций, Shadowsocks XHTTP REALITY, криптографического генератора и сохранности существующего JSON.
- `xray-studio-dialogs.js` — специализированные модальные окна.
- `scripts/check-xray-studio-enterprise.js` — проверки структуры и поведения read-only инспектора, интеграции кнопок и защиты секретов.
- `.github/workflows/backend-ci.yml` — запуск теста в CI.

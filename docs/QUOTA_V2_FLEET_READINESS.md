# Квоты v2 — предварительная проверка совместимости нод

## Текущее состояние

`XMESH_QUOTA_V2_ENABLED` остаётся выключенным по умолчанию. Одноразовый E2E-стенд с Node `control-v6.0.16` проходит тесты при `1`, но это **не** доказывает, что все установленные ноды или все Xray-обработчики в production готовы. Пока нет авторитетного подписанного *финального* счётчика Xray, автоматический досрочный возврат резерва запрещён; консервативное списание и отсутствие возврата остаются безопасной альтернативой.

## Запрос готовности

Авторизованный оператор с правами управления нодами может получить отчёт:

```http
GET /api/v1/quota-v2/fleet-readiness
```

В `nodes` для каждой ноды показаны:

- `reportedProtocolVersion`: версия из **аутентифицированного** запроса ноды (Ed25519 либо доверенный XSP-v2 product gateway) `/api/v1/node/desired-config`; отсутствие версии сохраняется как `0`.
- `lastAuthenticatedRequestAtMs`, `recentAuthenticatedRequest`: отметка последнего аутентифицированного обращения, годного только **15 минут**.
- `signedPolicyServedAfterClaim`: после данного обращения Nexus действительно сформировал и выдал подписанную политику.
- `protocolPreflightPassed` и `blocker`: причины незавершённой проверки `missing_or_stale_authenticated_request`, `legacy_or_missing_protocol_v2`, `no_signed_policy_served_after_claim` либо `none`. Выключенные ноды обозначены `excluded_disabled` и исключены из числа обслуживающих.

Поле `protocolPreflightPassed` в корне становится `true` лишь тогда, когда **каждая** неотключённая нода недавно аутентифицировала запрос v2 и после него получила подписанную конфигурацию. Пустой парк не считается готовым. Если нода снова аутентифицирует v1-запрос, статус немедленно ухудшается, даже если раньше она была v2. Секреты и приватные ключи в отчёте отсутствуют. Неавторизованный запрос запрещён.

## Что этот отчёт НЕ доказывает

Аутентифицированный запрос подтверждает только Node Ed25519-ключ либо авторизацию доверенного product gateway. Он не удостоверяет версию установленного бинарника Agent, применении политики всеми работающими процессами, фактической остановке Xray, сохранении последних байтов после сбоя или возможности возвращать резерв. Поэтому отчёт намеренно содержит:

- `installedAgentVersionAttested: false`
- `physicalStopAndFinalMeterVerified: false`
- `canRefundFromThisPreflight: false`
- `requiresNodeRolloutVerification: true`

**Нельзя автоматически менять `XMESH_QUOTA_V2_ENABLED` только на основании этого отчёта.** До переключения нужно независимо сверить фактически установленный Agent всех действующих нод, проверить подписанное применение политики и отсутствие старых выданных лимитов, пройти тестовый сценарий обновления/отката и доказать конечный учёт для полного набора транспортов. Нельзя принимать наблюдаемые (нефинальные) снимки Xray за подписанные терминальные доказательства.

## Зачем сохранять версии старых запросов

При включённом флаге Nexus отклоняет старый запрос без `quotaProtocolVersion=2` с HTTP 409 **до выдачи нового резерва**. Без проверки всего парка старые ноды потеряют возможность обновлять политику. Миграция `0130_quota_v2_authenticated_protocol_observations.sql` хранит только сведения о прошедших аутентификацию обращениях; сама она не управляет выдачей квот и не включает флаг.

Двухнодовый CI `scripts/test-quota-v2-e2e.py` проверяет пустую историю, неавторизованный запрос оператора, старый протокол, одну и две v2-ноды, устаревшую запись, повторное обращение и откат к старому протоколу. Тест запускается только на одноразовом Docker/PostgreSQL стенде.

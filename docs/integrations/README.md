# XMesh-Nexus Integration API v1

**Статус:** RFC, полный контракт запланирован, не внедрён в production.
[OpenAPI 3.1](./openapi.v1.json) описывает 76 операций по 57 путям.
Текущий исполняемый код реализует только ограниченный первый слой в draft PR #460.

## Назначение

Nexus отвечает за VPN-пользователей, сроки, доступ, подписки, трафик,
CDN/LTE, сквады, ноды и конфигурации. Внешние Telegram-боты и сайты
отвечают за тарифы, платежи, промокоды и общение с клиентами.
Бот не получает доступ к PostgreSQL и не использует cookie администратора.

## Авторизация

Все сервисные запросы через HTTPS и заголовок
`Authorization: Bearer <SERVICE_TOKEN>`. Владелец панели создаёт и
отзывает токены через защищённую веб-сессию с новой проверкой 2FA.
Токен состоит из 256 случайных бит; в PostgreSQL хранится только хеш.
Каждый токен имеет срок действия, разрешения и явный список доступных
userId или отдельно подтверждённый доступ ко всем пользователям.

Обычному VPN-боту достаточно разрешений `users:read`,
`subscriptions:read`, `traffic:read` и `entitlements:grant`.
Права `nodes:operate`, `system:update` и `credentials:rotate` ему
не нужны. Доступ к конкретному объекту проверяется дополнительно
к scopes. Запрос к чужому ID должен завершаться 404 без раскрытия
факта существования пользователя.

В ответе `users:read` НЕТ Xray UUID, паролей, ключей, Telegram
контактов и ссылок подписки. Получение ссылки — отдельное
`subscriptions:read`; операция чтения никогда её не перевыпускает.

## Примеры

```http
GET /api/v1/integrations/users/123
Authorization: Bearer <SERVICE_TOKEN>
Accept: application/json
```

Пример продления на 30 дней:

```http
POST /api/v1/integrations/users/123/entitlements/grant
Authorization: Bearer <SERVICE_TOKEN>
Content-Type: application/json
Idempotency-Key: 1f815d30-55e0-4c0d-bf25-6cd086f24531

{"days":30,"sourceReference":"grant-20261113-0293"}
```

Новый Idempotency-Key создаётся на одну логическую операцию.
При сетевом сбое бот повторяет тот же ключ и то же тело запроса.
PostgreSQL в одной транзакции записывает идентификатор операции
со стабильным clientId, блокирует пользователя FOR UPDATE,
пересчитывает срок, сохраняет ответ и аудит.

Повтор не начисляет дни дважды, в том числе после ротации
API-токена. Другое тело с тем же ключом возвращает 409. Nexus
не проверяет деньги — это обязанность бота. Неограниченную
подписку нельзя молча превращать в ограниченную; для hold=true
увеличивается отложенное время. Первое подтверждённое
VPN-подключение запускает срок, просмотр QR или ссылки — нет.

## Полные возможности

| Группа | Контракт |
| --- | --- |
| Пользователи | CRUD, блокировка, разблокировка, сроки, шаблоны |
| Подписки | Ссылка, клиентские форматы, явные revoke/reissue |
| Трафик | Суммарный, история, CDN/LTE, лимиты каждой ноды |
| Устройства | Лимит, список, отключение одного и всех |
| Telegram | Одноразовое подтверждение и уникальная привязка |
| Сквады | CRUD и массовое управление участниками |
| XRAY STUDIO | Конфигурации, проверки, хосты, маршруты |
| Ноды | Версии, диагностика, ограниченные фоновые команды |
| Статистика | Состояние инфраструктуры, метрики, активность |
| События | Надёжная очередь, курсоры и подписанные вебхуки |
| Система | Версии, обновления только с повышенными правами |
| Аудит | Действия с requestId без хранения секретов |

Полные схемы, ошибки, scopes и параметры каждого метода
находятся в [openapi.v1.json](./openapi.v1.json).

## Защита от злоупотреблений

Защита должна быть серверной: TLS, лимит попыток неверных ключей
до PostgreSQL, per-token rate limit после авторизации, bounded JSON
body, аудит, отказ при недоступности Redis, отсутствие CORS для
машинных токенов и отказ от браузерной cookie на сервисных путях.

Деструктивные операции требуют отдельного, подтверждённого
владельцем и краткоживущего полномочия. Нельзя выдавать обычному
боту произвольный PATCH внутренних JSON и приватных Xray ключей.
Аудит привязывается к clientId, но не логирует секреты.

Webhooks должны использовать транзакционный Postgres outbox,
HMAC-SHA256 подпись, проверку повторов, доставку с retry и
строгую SSRF-защиту: HTTPS, запрет private/loopback IP,
DNS rebinding, перенаправлений на приватные адреса и
ограничение времени соединения. Включённые галочки hooks
сами по себе не означают, что доставка событий реализована.

Стандартизованные ответы `data` и `meta`, ошибки RFC 9457 с
`requestId` и кодами 400/401/403/404/409/412/429/503,
постраничная навигация через курсоры, время UTC в
миллисекундах Unix для expiry, десятичные GB и точные байты.

## Условия выпуска

Обязательны Rustfmt, strict Clippy, миграции, unit и реальные
HTTP+PostgreSQL+Redis E2E тесты, параллельные повторы продления,
отзыв токенов, cross-client попытки доступа, массовое присваивание
полей и отсутствие утечек в логах. Нельзя маркировать маршрут
готовым, пока его обработчик не зарегистрирован и не проверен.

- [OWASP API Security](https://owasp.org/API-Security/)
- [RFC 9700 — Security Best Current Practice](https://www.rfc-editor.org/rfc/rfc9700)
- [RFC 9457 — HTTP Problem Details](https://www.rfc-editor.org/rfc/rfc9457)

PR #459 описывает полный API, PR #460 реализует только первый этап.

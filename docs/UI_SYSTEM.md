# XMesh Nexus Design System v3

Status: **authoritative panel design and composition contract**.

The panel has **one presentation entrypoint**: `nexus-ui-v3.css`.
The goal is simple: **the panel must be designed as a system, not repaired page by page.**

## Active architecture

The browser loads one content-addressed panel presentation entrypoint:
`frontend/styles/system/nexus-ui-v3.css`. It imports, in order:

1. `nexus-v3-foundation.css` — tokens, density, radii, Classic / Glass / Raised;
2. `nexus-v3-components.css` — shared surfaces, controls and dialog materials;
3. `nexus-v3-layout.css` — page-agnostic shell, workspace and responsive primitives;
4. scoped CSS files from `styles/features/` — feature-specific geometry, including Settings and Nodes.

The public subscription portal uses a separate stylesheet. The authenticated panel does
**not** load the retired legacy stylesheet, DOM-inference builder or fourth workspaces module.
See `scripts/check-ui-system.js` for the enforced asset graph. Cache keys are generated by
`node scripts/update-ui-cache.cjs`; do not invent query-string versions manually.

## Ownership model

### Foundation owns

- surface material and Appearance modes;
- global radius and border behavior;
- density scale;
- spacing/control tokens;
- compatibility token aliases where existing renderers still consume them.

### Components own

- `.card` and shared material surfaces;
- buttons, inputs, selects and segmented controls;
- table visual language;
- dialog material;
- focus / hover / selected states;
- nested-surface depth isolation.

### Layout owns

Only page-agnostic geometry:

- application shell and `.wrap`;
- generic `.view` flow;
- toolbar geometry;
- metric grids;
- low-count collections;
- empty-state sizing;
- tables and generic sparse states;
- editor/canvas exceptions;
- modal viewport safety;
- global responsive shell behavior.

`nexus-v3-layout.css` must **not** contain `.appearance-layout`, `.nodes-page` or any other complex page-specific workspace selector.

### Feature CSS owns

Only geometry or typography specific to a page, feature, editor or dialog. Settings and Nodes own their composition in their scoped feature styles, as do XRAY STUDIO, TLS/Reality editors, routing, diagnostics, user creation and subscription tooling.

Feature CSS must not implement its own Classic / Glass / Raised material, global button system, global card system, `.wrap`, `.view` or application-shell policy.

## Explicit runtime semantics

Renderers declare `data-workspace`, `data-ui-surface`, `data-ui-collection`
and toolbar/metric roles in their own markup. `frontend/js/core/app.js` owns route
rendering and explicit workspace metadata. There is no runtime UI builder.

Do not bring back mutation-based DOM classification, position arbitrary panels
from JavaScript measurements, or infer a page layout from incidental descendants.
Feature markup owns structure; system and scoped feature styles own presentation.

## Surface roles

Use these shared roles:

| Role | Purpose |
| --- | --- |
| `panel` | top-level card/workspace surface |
| `dialog` | modal shell |
| `section` | grouped content inside a surface |
| `metric` | KPI/stat tile |
| `item` | list/selectable item |
| `floating` | popover/dropdown |

Preferred markup:

```html
<section data-ui-surface="section">...</section>
```

Feature renderers declare roles explicitly; their materials come from the shared system.

## Width contract

The application shell's `.wrap` uses available width, while the route `.view`
applies explicit `data-workspace` sizing and the Appearance content-width limit.
This setting does not command each inner card or control to stretch.

- Data tables/lists use their assigned workspace responsively.
- Scoped features may set intentional, readable track caps. Nodes currently
  uses Compact 40rem, Standard 68rem and Spacious 76rem, left-aligned.
- Editors/canvases can use the assigned width when productive.
- Controls, copy rails and KPIs use proportional, readable internal tracks.

Do not globally narrow the shell to solve a feature's ultrawide geometry.

## Spatial contract

**Content-driven height is the default**.

A surface must not be substantially taller or wider than its meaningful content unless the extra space has a product purpose such as an editor, chart canvas, preview, drop zone or explicit empty state.

Avoid:

- decorative `min-height`;
- forced equal-height generic cards without a product reason (Nodes fleet deliberately aligns rows);
- `flex-grow` used only to fill the viewport;
- oversized padding that simulates importance;
- controls stretched simply because a track is wide;
- tiny information stranded inside a huge card;
- fixed-width KPI bottlenecks on a wide operational surface;
- hidden implicit grid columns;
- `display: contents` used to defeat meaningful workspace wrappers;
- separate full-width rows for tiny metadata that belongs in a toolbar;
- empty modal bodies/footers inherited from a larger editor layout.

**Low-count states recompose.** One or two objects should use deliberate, density-specific track sizes instead of preserving fleet-scale columns.

**Do not fill voids with fake UI.** Fix the geometry that created the void.

## Retired implementations

The following files and their behaviors have been removed and must not be restored:

- `frontend/styles/legacy/styles.css`;
- `frontend/js/core/ui-builder.js`;
- `frontend/styles/system/nexus-v3-workspaces.css`;
- `scripts/ci/stage-frontend-compat.sh`.

The modern panel imports scoped CSS through its single presentation entrypoint.
Do not add a fallback layer, synthetic compatibility files, DOM-inferred layouts
or a second global style authority. `scripts/check-ui-system.js` enforces their absence.

## Material contract

Appearance remains authoritative:

- `data-surface="solid"` → Classic;
- `data-surface="glass"` → Glass;
- `data-surface="raised"` → Raised.

Glass must use real transparency/backdrop blur unless the OS requests reduced transparency.

Raised is a neutral depth hierarchy, not an accent-tinted theme. Accent belongs to selection, focus, status and primary action.

Nested modal sections do not stack outer shadows or backdrop filters. A dialog has one primary material shell.

Separators are structural and remain quieter than surface borders, including Strong border mode.

## Interaction contract

Bloom is not an interaction primitive.

Surfaces/cards must not acquire neon glow or floating lift on hover. Shared interactive controls may use the existing subtle press/hover motion. Selected state must remain more obvious than hover. Keyboard focus uses the shared focus token.

Composite controls have one material shell; inner native inputs remain transparent/borderless.

## Core composition rules

### Settings

Settings uses two real workspace columns on wide desktop: approximately 54/46 rather than six independently positioned cards.

Requirements:

- `.appearance-column` remains a real grid wrapper;
- cards are content-height, never forced equal-height;
- old explicit `grid-area` placement is neutralized;
- title/description anatomy stays quiet and consistent;
- controls use a readable right rail instead of a half-screen stretch;
- palette presets use a stable full-card grid;
- font selection is a structured chooser, not a wrapped sentence;
- custom-palette and range controls reflow before clipping;
- responsive behavior is based on actual workspace width through container queries.

Decorative pseudo-icons must not be generated merely to make Settings look “premium”. Hierarchy comes from typography, spacing, material and grouping.

### Nodes

The active owner is `frontend/styles/features/nodes/nodes.css`; `nodesP()` in
`frontend/js/core/app.js` renders the anatomy. The three-system-module asset
contract is enforced by `scripts/check-ui-system.js`.

- Nodes tracks are anchored to the left workspace edge and capped by density: Compact 40rem, Standard 68rem, Spacious 76rem.
  Cards and their action buttons stop stretching across ultrawide low-count fleets;
  narrower workspaces still shrink the tracks to fit. Global radius settings remain authoritative.
- Compact is the square-card experiment: summary above telemetry, a separating line,
  and three horizontal KPI tiles at readable card widths. Its proportions follow
  content, with no forced aspect ratio or clipped actions. Four action columns fit
  from a 36rem content width; narrower cards retain the two-column fallback.
- The header groups flag/name/endpoint/provider on the left and runtime badges on the right.
- `.node-body` is a real grid: summary 40%, telemetry 60% once the card has room.
- Users and XRAY STUDIO are adjacent summary columns with a vertical divider.
- TLS retains its shield during runtime updates; GeoData retains its status dot.
- Three equal-height KPI tiles share one row above the full telemetry speed rail.
- Actions use four equal columns, four equal columns, then full-width Create Host.
  Only narrow cards reflow to two columns.
- Card depth comes from `--nx-panel-shadow`; accent outer bloom is forbidden.
- Compact / Standard / Spacious change actual fleet track geometry.
- Equal fractional fleet rows and stretched cards keep every rendered card at
  the same content-driven height, across rows and runtime states. The middle
  body absorbs available space, keeping telemetry and actions at the bottom;
  no fixed card height or runtime DOM measurement is used.
- Container queries use card width for anatomy and workspace width for fleet density.
- Icons come from the shared `ic()` SVG renderer.

### User Details

`workspace-dialog-contract.css` owns final dialog geometry; `user-details.css`
owns feature content. The desktop height budget uses the viewport minus its safe margin, so content
can grow beyond the former 54rem cap when the screen has room. Header, usage band, task tabs, shared Save action and footer stay in flow without shrinking.
Settings, Access & subscription, Traffic and Devices use one intrinsic panel grid.
Inactive panels remain mounted with `inert` and `aria-hidden`, preserving the
shared settings/access draft and dialog geometry. Arrow keys, Home and End move
between tabs. Validation reveals the affected panel; errors stay outside panels. `.user-canvas-grid` is the single scroll owner
with a stable scrollbar gutter. `userDrawer()` resets that owner's scroll
position after mounting, including when another user replaces an open dialog.

Browser acceptance lives in `scripts/test-ui-browser.cjs`: real DOM rectangles,
semantic icons after runtime refresh, neutral computed shadow, 4 + 4 + 1 actions,
viewport-safe height without the former 54rem cap, pane baselines, and reopening after a real scroll.
Artifacts include `nodes-{width}x{height}.png` and
`user-details-{width}x{height}.png` at 1920×1080, 2560×1440 and 3440×1440.

### Tables / Users / Squads / Hosts

Short tables are short surfaces. They do not reserve fleet-scale height. Empty page background below real content is preferable to artificial stretching.

Large data sets may use more horizontal space, but form controls and text still need deliberate reading widths.

Host editor markup and Node → Host country/remark presets belong to
`frontend/js/features/hosts/host-editor.js`. Its classic-script factory receives
live profile/node getters, profile/inbound lookup and the existing field/icon/
escaping helpers plus the country catalog. It owns no DB copy or route state.
`app.js` supplies the adapter and retains live preview, validation, X25519,
event dispatch and submit ownership. The module does not define styles or a
second control/material system.

### Empty states / Templates / Balancers

Empty states stay compact and explicit. They do not become half-screen blank cards.

### Editors

Editors own useful working area. Global compaction must not shrink code, chart, JSON or canvas surfaces that benefit from height or width.

## Migration rule

When touching a feature:

1. preserve behavior and data semantics unless explicitly requested;
2. inspect the active importer, renderer and selector ownership before editing CSS;
3. keep material, global tokens, controls and shell in their three system owners;
4. keep Settings, Nodes and other page-specific composition in scoped feature CSS;
5. declare collection, surface and workspace semantics explicitly in markup;
6. avoid DOM-inference builders, global overrides and new presentation layers;
7. retire obsolete source contracts instead of enforcing historical CSS structure;
8. regenerate content-addressed cache keys with `node scripts/update-ui-cache.cjs`.

Do not restore the retired legacy stylesheet or compatibility staging scripts.

## Frontend ownership audit

For every CSS change, review the whole selector scope, not just the screenshot being repaired.

A feature stylesheet is suspicious if it defines any of the following without a feature root:

- `.wrap`;
- `.view`;
- `.app` shell geometry;
- `.card` material;
- `.btn`, `.gh`, `.seg` global visual language;
- `html[data-surface=...]` or equivalent Appearance forks.

The current panel source contract rejects `display: contents` in panel CSS; keep real layout wrappers and their boxes.

## Review checklist

Before merging UI work:

1. Classic / Glass / Raised remain distinct; dark/light themes stay usable.
2. Radius, border, density, content width and motion settings still work.
3. The presentation graph has three system CSS owners plus scoped feature imports.
4. Retired builder, legacy CSS, workspaces module and staging script remain absent.
5. Shared material and global shell selectors stay out of feature CSS.
6. Generic layout stays free of page-specific Settings/Nodes selectors.
7. Settings/Nodes geometry uses feature owners and appropriate container queries.
8. Nodes keeps its approved density caps and action/icon anatomy.
9. No new accent bloom, generic card lift or double material shell is introduced.
10. No accidental dead regions, clipping, overlap or document overflow.
11. Short content remains content-height, while editors retain purposeful workspace.
12. Browser geometry, interactions and screenshots agree with the implementation.

## CI contract

The primary architecture check is:

```bash
node scripts/check-ui-system.js
```

Nodes composition is additionally protected by:

```bash
node scripts/check-node-grid-layout.js
```

The checks enforce content-addressed runtime assets, three system owners plus scoped features, absence of retired implementations, shared material primitives, explicit workspace semantics and feature-scoped Nodes geometry. Browser acceptance lives in `scripts/test-ui-browser.cjs`.
